# KES integration design

The source frontend runs before selection discovery, comment removal, and ordinary Lua parsers. A token lexer excludes comments and strings; a recursive statement parser and Pratt expression parser lower only extended constructs. Standard inputs take a lexical feature check and retain their exact text. The public lowering result includes a generated-to-original position map. Errors from this frontend use original Unicode line/column coordinates.

Compound assignment evaluates receiver, key, old value, then right operand, once each; the final write follows the operator. Nil assignment reads once and writes only for nil. Lazy expressions produce one result, preserve false, and use lexical Lua functions to avoid global helpers. Free varargs are forwarded explicitly. Ternary is right associative, below `??`, `or`, and `and`; `??` is right associative below `or`.

Continue uses a one-iteration repeat wrapper on both Lua versions. A separate flag distinguishes the source loop's break. Return and nested-loop control retain their owners. Repeat-body declarations visible in the until condition receive unique lexical bindings outside the wrapper, freshly initialized each iteration; a declaration skipped by continue has nil value in the condition. This intentionally defines the previously invalid source construct. Initializers retain their original lexical scope. No goto is introduced. Floor compound assignment is rejected for Lua 5.1.

Intrinsic names are reserved only as identifiers, and are permitted solely as direct calls with fixed arity. Validate them before source passes and preserve their global lookup through localization. Immediately before compilation, parsed bare calls receive collision-free private symbols. This distinguishes them from table keys or strings with the same public spelling. Resolve those compiler-produced global-load/call sequences into typed Semantic IR operations before optimization/protection; refuse any unresolved use. Existing information opcodes are reused. Failure opcodes are appended to the physical ABI.

Abort raises a generic Lua error for the current execution. Assert consumes one condition and aborts if falsy; Unreachable always aborts. Panic also poisons the enclosing runtime instance. All physical VMs and closures created by one emitted runtime share the poison state, including suspended coroutines and closures returned to native callers. Every interpreter dispatch and entry checks it, so catching the error cannot resume that instance. Independently loaded outputs and independently emitted selective runtimes remain separate. Host error catching remains possible.

Selection decides actual VM placement; an intrinsic must not activate a VM pass. Residual native intrinsic calls are rejected before packing can hide them. GUI source execution lowers convenience syntax and rejects VM intrinsics. Tests compare syntax to independently written Lua oracles and inspect intrinsic IR/runtime contracts separately.
